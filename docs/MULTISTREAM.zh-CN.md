# 多流 ASIO 桥接（实验版）

本版本提供可保存的通道分配，先完成“两条 8 通道流进入 ASIO 1–16”的链路。
CLI 统一收包和写入共享音频环；每条流占用独立的目标通道。
反向链路从共享 capture 环读取一次，再按同一份配置拆成多条 RTP 流。
Qt 界面暂未接入路由编辑器。

## 启动

先按主 README 构建和注册 ASIO 声卡。复制 `examples/two-8ch.routes`，
将组播地址、端口、编码和 payload type 改为设备的实际 SDP 参数。
在仓库根目录执行：

```powershell
.\build\openaes67.exe routes --routes examples/two-8ch.routes
.\build\openaes67.exe multibridge --routes examples/two-8ch.routes --iface <有线网卡IPv4>
```

然后在 DAW 中以 48 kHz 打开 `OpenAES67 ASIO 64x64`。
默认共享区为 `OpenAES67Audio`；可用 `--shm NAME` 与声卡的
`OPENAES67_SHM` 环境变量配合。一次只运行一个音频泵，启动前停止旧的 `bridge`、
`recv --shm`、`send --shm` 等程序；新的互斥锁只约束 `multibridge` 实例。
已有共享区必须是 64 通道、48 kHz、int16，启动不会清空已有读写位置。

默认持续运行，Ctrl+C 正常停止。`--seconds 10` 可限制运行时长，`0` 表示持续运行。
这两个新命令只接受 `--routes`、`--iface`、`--shm`、`--seconds`、`--render-ms`。
`--render-ms` 是整数，范围 5–50，默认 10，控制共享 render 队列的目标时长。
队列应覆盖至少一块宿主缓冲并留出调度余量：64–256 帧可用默认 10 ms，
2048 帧应使用 `--render-ms 50`。较深队列会增加延迟；已有共享区容量必须容纳该队列。
配置在启动时加载；编辑文件后重启即可恢复保存的通道表，暂不支持热切换。

## 路由格式

每行七个字段，以空格分隔；`#` 后是注释。支持 UTF-8 和带 BOM 的 UTF-16 文件。

```text
# 方向 组播地址 UDP端口 通道数 ASIO起始通道 编码 PT
rx 239.69.1.1 5004 8 1 L24 97
rx 239.69.1.2 5006 8 9 L24 97
tx 239.69.2.1 5010 8 1 L24 97
tx 239.69.2.2 5012 8 9 L24 97
```

- `rx` 将网络通道送到 DAW 的 ASIO 输入；`tx` 将 DAW 的 ASIO 输出送往网络。
- ASIO 通道从 1 开始。每条流 1–8 通道，每个方向最多八条，总范围 1–64。
- 接收通道不得重叠；发送端允许复用同一输入通道，用于分发。
- **所有路由的 UDP 端口必须互不相同**，避免 Windows 同端口组播套接字交叉收包。
- 编码为 `L16` 或 `L24`，动态 PT 为 96–127，必须匹配设备 SDP，不能仅凭编码推测。
- 固定 48 kHz、1 ms（每包 48 帧）。L24 仍转换到现有 int16 内部链路，低八位不保留。

## 时间、断流和诊断

接收端要求各流具有相同的 RTP 媒体时间基准，不能将任意两个独立 RTP 会话
按到达时间强行对齐。本版不验证 PTP grandmaster 或 SDP 的时钟属性，部署前应确认。
首包建立时间轴，预缓冲至少 30 ms；配置较大 render 队列时预缓冲随之延长，
最大为 50 ms。每帧按 RTP 时间戳写入固定容量缓冲区。
乱序包回到对应时隙，重复包保留第一份，迟到或超出约 170 ms 窗口的包被丢弃。
接收泵根据 ASIO 的实际读位置补帧，共享 render 队列默认目标约 10 ms。
声卡每次消费的帧数可以不同，泵不再假设宿主每毫秒一定读取 48 帧。
若共享区启动前已有旧数据，会让宿主自然读出，不修改宿主拥有的读索引。
某流缺包时只将其通道填零，其余流继续。全部接收流停止一秒后，清空时间轴，
允许新的 RTP 时间基准重新建立。单流重启保留原时间基准时可恢复；单流改用
独立时间基准时，应停止全部接收源一秒以上再重启。SSRC 在仍活跃时不会混用。

接收侧按剩余 RTP 时间跨度作缓冲反馈，每 128 ms 平均一次，目标 30 ms，
校正限制为 ±2000 ppm。所有路由使用共同的分数相位作线性插值，避免各条流
独立重采样产生相位偏移。比例变化时会改变采样值，不是无损重采样。
它吸收小幅网络/宿主速率差，不提供 PTP 锁定，也不能替代共同媒体时间基准。
接收源安静超过 100 ms 时不再将缺包当成时钟误差累积。ASIO 读位置停止前进
250 ms 后标记为等待宿主；恢复读取时重建接收时间轴并重新预缓冲，避免播放
暂停期间堆积的网络数据。共享环中已有的少量排队帧仍由宿主自然读出。

发送流使用共同的本地时间戳，每毫秒递增 48，发送侧仍用本机计时器驱动。
尚无发送侧速率校正、PTP 驯服、SAP 或 RTCP。主机调度落后超过
5 ms 时跳过错过的时间间隔并重建接收预缓冲，不连续追赶发送大量包。
超出接收校正范围、调度长时间停顿或发送时钟不匹配仍可能造成缺帧与积压。

停止时输出累计计数：`rx`/`tx` 是接受/发送包数；`rejected` 包含格式或 SSRC
不匹配；`timestamp_rejects` 为迟到或超出时间窗口；`missing_channel_frames`
为已映射接收通道的缺失帧；`render_dropped` 和 `capture_missing` 表示共享环
写不下或读不够的帧数；`restarts` 为接收时间轴重建次数；`schedule_resets`
为主机调度中断次数。持续异常需检查配置、时钟及宿主是否正在消费音频。
启动失败返回非零；网络发送出现错误时最终返回 3。

每秒输出 `rx_host`、`rx_buffer`、`render_pending` 和 `rx_correction`：
分别表示接收宿主是否在读、接收时间轴剩余帧数、共享队列帧数及校正 ppm。
`rx_buffer` 包含丢包空洞，不能当成每条流都有的有效音频帧数。
停止时还输出 `host_pauses`、`host_resumes` 和 `waiting_host_packets`。
这些宿主状态描述接收方向，单独使用发送路由时不检测 render 宿主。

## 验证范围与下一步

`build.bat` 构建并运行 `build/multibridge_test.exe`；CMake 与 GitHub Actions
运行 `openaes67_multibridge_test.exe`。测试包含参数拒绝、通道隔离、乱序、
重复、时间戳回绕、缺包补零、共享环重附着，以及实际 UDP 组播回环和模拟 ASIO 宿主。
回环测试不需要音频设备，但需要 Windows 允许本机组播。

这些验证不代表真实设备互通。八小时实机验证待完成：记录设备与固件、交换机、
PTP 域及主时钟、两条流 SDP、DAW 缓冲大小、通道信号、断流/恢复时间、计数器
和可听异常。后续继续补 PTP 与发送侧时钟适配，再做 GUI 路由矩阵与真正的 24 位链路。

## 接收时钟适配验证（2026-11-15）

专用多流测试扩展至 108 项检查。以下虚拟时钟测试各运行两分钟模拟时间，
使用 256 帧宿主读取块；包含 RTP 时间戳回绕和两条流共同相位检查。
均无缺样或迟到包；缓冲范围取开始 20 秒后的样本，校正均值取最后 20 秒。
这不是实机运行时间，也不是声学延迟测量。

| 网络偏差 ppm | 宿主偏差 ppm | 校正均值 ppm | 缓冲帧范围 |
|---|---|---|---|
| +100 | 0 | +108.3 | 1265–1600 |
| -100 | 0 | -91.5 | 1229–1598 |
| 0 | +500 | -494.2 | 1218–1596 |
| 0 | -500 | +494.0 | 1280–1594 |

UDP 回环分别使用 48、256、2048 帧的模拟宿主缓冲，每组运行 4.2 秒，
另注入一次 400 ms 宿主暂停，验证共享队列不超过配置值、宿主块读取完整，
恢复后重新接收新信号，以及实时状态回报。前两组使用 10 ms 队列，
2048 帧组使用 50 ms 队列；时间戳窗口扩大到 8192 帧以容纳大块预缓冲与宿主周期。
一次 CMake 样本中，48 帧组接收 5021 包、发送 8396 包，256 帧组接收 5006 包、
发送 8398 包，2048 帧组接收 4818 包、发送 8398 包；三组均重建接收时间轴 1 次、
调度重建 0 次。包数随调度变化，不作为固定断言。

本次 `build.bat` 与 CMake Release / Qt GUI 构建通过，两套多流检查通过，
原有 321 项自检及文档声明校验通过；ASIO DLL 构建和 2 秒宿主接口测试通过。
既有八项性能基线检查通过（三次最好值、15% 阈值），敏感信息扫描无发现。
